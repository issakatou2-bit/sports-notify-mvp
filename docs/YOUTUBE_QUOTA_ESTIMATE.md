# YouTube の取得方法と字幕の枠の見積もり

確認日: 2026-10-14。対象コード: main `09b1ea3e`。実GCPの使用量・上限は未確認。

## 今回の判断

`videos.batchGetStats` は利用できる新メソッドだが、今回の `data/analytics.json` / `early_views` の取得は置き換えない。認証・リポジトリ変数・字幕の上限は変更しない。

- `scripts/fetch_analytics.py` の再生数・視聴時間・維持率・流入元は **YouTube Analytics API** の期間集計。新メソッドは Data API の累積再生数などであり、期間・指標が違う。ここを置き換えると分析の意味が変わる。
- 同ファイルの `videos.list(part=snippet,contentDetails)` は題名を添えるため。新メソッドの `snippet` は `publishTime` のみで題名を返さない。
- `scripts/early_views.py:stats_for` は既に50本ずつまとめ、1呼出し1単位。再生数だけでなく `status.privacyStatus` と `snippet.publishedAt` を使い、非公開・欠測・公開後の時間帯を区別する。新メソッドに `status` はない。`publishTime` を既存の実公開時刻と同じものと未確認で扱わない。
- 状態確認用に従来の取得を残して統計だけ分離すると、通常枠の呼出し回数は減らず、別枠の呼出しが追加になる。字幕用に空く通常枠は **0単位**。したがって今回の取得経路では交換の利点がない。
- 純粋に公開動画の累積統計だけを読む用途（例: `mlb_buzz.py` / `soccer_buzz.py`）は候補。ただし今回の分析取得の交換とは別件。認証なしの返却だけで非公開判定を推測しない。

公式の[batchGetStats仕様](https://developers.google.com/youtube/v3/docs/videos/batchGetStats)で経路・応答項目を確認した。手元の `googleapiclient` 同梱の公式 discovery 定義でも `videos().batchGetStats`、GET `videos:batchGetStats`、ID上限50件を確認した。実YouTube APIの応答・OAuthは未検証。試験のために投稿や有料サービスの登録は行っていない。

## 標準の枠（実プロジェクトの値とは別）

| 枠 | 公式の標準上限/日 | 数え方 |
|---|---:|---|
| 投稿 `videos.insert` | 100回 | 1呼出し=1回。通常枠とは別 |
| 検索 `search.list` | 100回 | 1ページ=1回。通常枠とは別 |
| 新統計 `videos.batchGetStats` | 10,000単位 | 1呼出し=1単位。通常枠とは別 |
| その他の Data API | 10,000単位 | メソッドごとの単位を合計 |

[改訂履歴](https://developers.google.com/youtube/v3/revision_history)で、投稿/検索の分離が2026-06-01、新統計が06-03と確認。上限の実値はGoogle Cloud Consoleで別に確認が必要。日次リセットは米太平洋時間0時（夏時間中は日本16時、冬は17時）。JSTの日付と枠の日付を混ぜない。

## 字幕・分析の見積もり

以下は[公式の単位表](https://developers.google.com/youtube/v3/determine_quota_cost)と今回のコードを使う**計算例**。実使用量ではない。字幕1本は既存確認 `captions.list` 50＋新規 `captions.insert` 400＝**450単位**。既に字幕がある場合は50、更新なら `captions.update` 450＋確認50＝500。失敗したリクエスト・追加ページ・再実行も消費する。

| 英語字幕の本数/日 | 英語字幕だけ | 日本語字幕1本＋英語字幕 | 日本語字幕8本＋英語字幕（仮定） |
|---:|---:|---:|---:|
| 1 | 450 | 900 | 4,050 |
| 3 | 1,350 | 1,800 | 4,950 |
| 5 | 2,250 | 2,700 | 5,850 |
| 8 | 3,600 | 4,050 | 7,200 |

mainでは `daily_notify.yml` が日本語字幕と英語字幕を呼ぶ。`ps_game_now.yml` は試合直後の英語字幕を追加しうる。日本語8本の列は上限検討の仮定で、全8枠に現在字幕が送信されるとの実績報告ではない。APSCの字幕も同じGCPを使うなら通常枠に加算する（投稿が別枠でも字幕は別枠にならない）。

| 取得/処理 | この版での概算 |
|---|---|
| 初動（直近7日、手元の保存台帳） | 2026-10-14時点71 ID、50件ずつ2呼出し＝通常枠2単位/実行。ライブ件数ではない |
| 初動を新統計＋状態の従来取得に分離 | 通常枠2＋統計別枠2。通常枠節約0 |
| Analyticsに添える題名 | 最大200 IDなら通常枠4単位/実行。Analyticsの期間指標・離脱曲線は別APIの制限 |
| 題名等の更新 `videos.update` | 50単位/呼出し。翻訳・ローカライズの本数も加算 |
| 投稿/検索 | それぞれの独立枠。以前の1600単位/投稿で通常枠を引き算しない |

残量判定式: `通常枠の実残量 − 他プロジェクトの字幕/更新等 − 本処理で使う通常枠 − 予備1000 >= 英語字幕追加本数×450`。

例えば他の通常枠消費を500、予備1000、日本語8本を3600と仮定した場合、英語3本では合計6450で残り3550。ただしAPSCで11本に字幕を1言語ずつ付けるとさらに4950なので、合計11400となり標準枠を超える。APSCの11投稿だけなら投稿枠を11回使う計算で、この4950は加えない。

英語1→3本の追加は900単位/日。増やす提案は、共通GCPの**その他の Data API枠**の残量と字幕の失敗記録を確認してから。`english_captions.py` の400単位というコメントはinsert分だけで、list込みは450。既定の本数制限、予備枠、共有の残量観測、PT日付の検査は維持する。新枠が存在するというだけで、英語字幕上限を自動で増やさない。
