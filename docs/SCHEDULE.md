# コレスポの編成と、投稿時刻を決めた理由

更新: 2026-09-14 / Claude（エマ）

前半が**いま何をいつ出しているか**の一覧、後半が**なぜその時刻か**の台帳。
時刻そのものは各ワークフローに書いてある。

---


**生成と公開は別の時刻。**生成はGitHubの都合で早めに走らせ、公開は
YouTubeの予約投稿（`--publish-at`）で決めている。GitHubのscheduleは
2〜4時間遅れるので、生成時刻をあてにしない。下の時刻はすべて**公開**の時刻。

## 毎日

**2026-09-15に30分刻みへ揃えた。**17:00から21:00の間だけを使う。

| 公開(JST) | 枠 | 形 | 中身 | 実測（8/16〜9/13） |
|---|---|---|---|---|
| 17:00 | 日本人選手の成績 | 縦・短 | その日の成績を点数順に。名前のある記録は金の帯、本塁打は飛距離 | **34本 平均433 視聴率104.5% 登録8** |
| 17:30 | ファンのコメント欄 | 縦・短 | MLB公式ハイライトのコメント | 23本 平均111 58.9% |
| 18:00 | 現地の報道 | 縦・短 | 日本人選手を扱った記事と番記者の投稿 | 20本 平均291 28.2% 登録2 |
| 18:30 | 資産動画 | 縦・短 | 球団・サッカー・指標などの常緑もの | 52本 平均154 42.0% 登録2 |
| 19:00 | 明日の注目試合 | 縦・短 | 翌日の先発と見どころ | 27本 平均275 35.3% 登録3 |
| 19:30 | 欧州サッカー | 縦・短 | その日の欧州の試合 | 22本 平均171 58.3% |
| 20:00 | ポストシーズン進出争い | 縦・短 | 地区とワイルドカードの線（9〜10月のみ） | **11本 平均100 視聴率206.9%** |
| 21:00 | きょうのMLB、数字で（3分） | 横・長 | **その日の数字**（9/14に切替。旧：公式コメント欄） | 6本 平均16 39.3% |

- 合計 **1日8本**。本数は減らしていない。
- **同じ時刻に2本出すと、2本目が必ず負ける。**実測がある——8月に
  17:00へ2本置いた3日間で、向きは一度も反転せず、差は818回対40回の
  20倍まで開いた。それでも9/15まで18:00と19:00に2本ずつ残っていた。
- 時刻の順は強さではなく**中身の時間依存性**で決めている。
  その日の結果（成績→コメント欄→報道）が先、日付に依存しない資産動画が中間、
  明日の予告が19:00、今夜のキックオフ前がサッカー、順位表が20時台、
  腰を据えて見る横型が最後。

## 週次

**2026-09-15に週間まとめを止めた。**4本出して、YouTubeの再生の集計に
1本も入っていない（実質0再生）。中身も日次の寄せ集めで、
ユーザーの判断は「やっつけにしかなっていないので一旦止めていい」。
ワークフローは消していない（`weekly_summary.yml` の `workflow_run` を
外しただけ）。替わりが決まれば戻すだけで動く。

## 節ごと・不定期

| 公開 | 枠 | いつ | 中身 |
|---|---|---|---|
| 20:30 | 欧州サッカー 順位争い | **その大会の節が全クラブ終わった日** | 1本1大会。CL圏内・EL圏内・残留の境目 |

- 38節のリーグは5節から、CL（全8節）は3節から出す。
  CLの第1節は勝点0・1・3の3種類しか無く、順位表が成り立たない。
- **9/14に投稿を開けた。**自動で動き出すのは国内リーグ5節（9月末）、
  CLは3節（10月下旬）。それまで実際には出ない。

## 動画以外

| 先 | 何を | いつ |
|---|---|---|
| X / Instagram / TikTok | 明日の注目試合（1本だけ）| 19:00の直後。Buffer経由 |
| TikTok | 夕方の4本 | 各枠の公開時 |
| Podcast | 明日の注目試合の音声 | 19:00の枠で生成 |
| Web (collespo.com) | 成績・順位表・選手ページ | 定時更新 |
| プッシュ通知 | 明日の注目試合 | 19:00の枠 |

- Bufferの配信結果は19:47と23:47に照合する。TikTokの取り込みは
  6分では終わらないことが多く、**「処理中」は失敗ではない**（9/14に修正）。

## 見えている問題

1. **資産動画の在庫が5件。**毎日1本出しているので5日で尽きる。
   用語(平均8再生)・球場(4)・NPB(4)を止めたぶんの穴で、
   名前のある指標（`rare_topics.py`）で2件足したが足りない。
   球団ものは30球団を出し切っている。**新しい種類が要る。**
   ユーザーから「以前から言っていた」との指摘。いちばん古い宿題。
2. **週間まとめの替わりが未決。**枠は止めた。何を入れるかは決まっていない。
3. 長編を数字に切り替えたのは9/14。**再生はまだ見ていない。**
   9/15の回で、材料に「その数字が普通か珍しいか」が入っていないために
   当たり前のことを珍しがる台詞が出た（3ランの3打点を「多い」、
   救援の1回を「短い」）。材料と台本の指示を直したのは9/15。

## 何もない期間に、空の動画を出さないための約束

シーズンやポストシーズンが終わると、**材料は更新が止まったまま残る。**
中身は正しいので検算では捕まらない。日付と決着で切る。

| 枠 | 何で止まるか |
|---|---|
| 日本人選手の成績 | 出場した選手がいなければ作らない |
| 明日の注目試合 | 注目試合が0件なら作らない |
| 現地の報道 | 素材が3件未満なら作らない |
| ポストシーズン進出争い | **全球団の行き先が決まり、動きも無ければ作らない**（9/15追加） |
| きょうのMLB、数字で | **材料が3日以上古ければ使わない**（9/15追加） |
| 欧州サッカー | 対象の試合が無ければ作らない |
| 欧州サッカー 順位争い | 季が終わっていれば出さない。出した節は季ごとに覚える（9/15追加） |
| 資産動画 | 日付に依存しない中身なので、在庫があるかぎり出してよい |

検査は `scripts/test_offseason.py`。

## 数字の読み方（判断の土台）

- **題に日本人選手の名前があるかで倍以上変わる。**登録もほぼ全部そこから。
- 順位表の回は**繰り返し見られる**（進出争いの視聴率206.9%）。
  数字を確かめに戻ってくる種類の画面。
- **初動が3分の1に落ち、視聴率と視聴秒は上がっている。**
  直近7日は56本で平均初動61・視聴率70.5%・48秒。
  その前7日は55本で初動170・46.8%・34秒。
  配られる量が減って、見られ方は良い。本数（1日8本）が怪しいが
  **断定できていない。**

# なぜその時刻なのか（考え方の台帳）

> **この節に書いてある時刻の数字は古い。**枠の入れ替えがあったのに
> ここを直していなかった（「今日の1人」「現地での注目度」はもう無く、
> サッカーは20:00ではなく19:00、現地の報道は21:00ではなく18:00）。
> **いま何時に出ているかは、このページの前半を見ること。**
> ここに残す価値があるのは、**どういう場面を想定して置いたか**のほう。

投稿時刻を決めた理由の台帳。時刻そのものは各ワークフローに書いてあるが、
「なぜその時刻か」はどこにも無かった。無いと、ずらすときの判断ができない。

実測（YouTube Analytics 直近28日）を先に置く。ここが前提になる。

| 見ているもの | 数字 |
|---|---|
| 視聴の入口 | Shortsフィード 7,529回 / 検索 238回 / チャンネル 28回 |
| フィード経由の視聴時間 | 平均 **21秒** |
| 検索経由の視聴時間 | 平均 **102秒** |
| 端末 | モバイル 6,952 / デスクトップ 432 / テレビ 184 |
| 国 | 日本 100% |
| 年齢 | 45-54歳 23% / 55-64歳 21% / 35-44歳 15% / 25-34歳 15% |
| 離脱 | どの枠も 12〜21%地点（8〜14秒）で急に減る |

つまり **ほとんどの人はフィードで20秒だけ見る**。検索で来る人は少ないが
5倍見る。この2種類の見られ方に、それぞれ用意する。

## MLBの試合が日本時間のどこにあるか

これが全部の前提になる。米国東部の夜（19:00前後）＝日本の朝（8:00前後）。

```
 日本時間  00      06      12      18      24
           |       |       |       |       |
 MLB       ====前夜の続き====                 ←未明〜昼に試合
 結果確定                ▲14:25前後
 夕方の4本                     ■■■■■        17:00-18:00
 明日の試合                        ■         19:00
 欧州サッカー                        ■        19:00（キックオフの3時間前）
 現地の報道                          ■       18:00
 資産動画                             ■      22:00
```

---

## 枠ごとの想定

### 16:30　日本人選手の成績
**場面**: 仕事や学校が終わって、その日の結果をまだ見ていない人。
最終試合の終了（実測14:25前後）から2時間置いてある。延長があっても
確定しているのがこの時刻。**その日いちばん早く結果に触れる枠**。

### 17:00　今日の1人
**場面**: 選手名で検索してきた人。移動中でも通勤前でもよい。
**この枠だけ日付に依存しない。** タイトルに「今日の」を入れないのは
そのため。1年後に「Pete Crow-Armstrong 成績」で検索した人にも
同じだけ役に立つ。実測でも常緑ものは維持率76.3%と、日次の倍以上。

### 17:30　ファンのコメント欄
**場面**: 帰宅前のいちばん軽い時間。事実の確認ではなく、
現地がどう沸いたかを覗く回。3本のうちいちばん頭を使わない。

### 18:00　現地での注目度
**場面**: 帰宅の移動中。数字（再生回数）と話題のチームなので、
音を切っていても画面だけで通る。

### 19:00　明日の注目試合
**場面**: **夜、寝る前。翌朝の起きる時間を決めるために見る。**
MLBは日本の朝8時前後に始まるので、この時刻に「明日はこれ」を出せば、
早起きするかどうかを決められる。「毎日19時」を約束にしているのも
そのため（毎日同じ時刻でないと、決める材料にならない）。

### 20:00　欧州サッカー
**場面**: 欧州の試合開始前。現地20:00キックオフ＝日本の未明。
その前に「今夜は何がある」を渡す。MLBと分けているのは、
MLBは「明日」、サッカーは「今夜」で、1本にまとめるとどちらかが嘘になるため。

### 21:00　現地の報道
**場面**: 一日の終わり、腰を据えて読むもの。日本の視聴が最も多い
20〜22時に、いちばん読み物寄りの回を置いている。

### 22:00　資産動画（球場・球団・用語）
**場面**: 寝る前。あるいは後日の検索。日付に依存しないので、
この時刻に出すこと自体には意味が無い——他の枠を邪魔しない時間、
というのが理由。実際の視聴はここから何日もかけて積み上がる。

### 毎週日曜　週間まとめ
**場面**: 横型8分。テレビか、腰を据えて見る場面。
実測でテレビからの視聴は維持率116%（＝ループしている）で、
数は少ないがいちばん深く見られている。

## この配置で埋まっていないもの

- **朝**（通勤通学の時間帯）に1本も無い。前夜のうちに全部出し切っている。
  MLBの試合が朝〜昼なので、朝に出せる確定した結果が無いのが理由。
- **サッカーの試合が無い日**は、サッカーを見に来た人に何も届かない。
  2026-08-18 がそうだった（欧州0試合）。ここは埋めるべき穴。

---

## 時刻ぴったりに出るもの／出ないもの

同じ「毎日◯時」でも、仕組みが2つある。混ざっていると、
ずれたときに不具合なのか仕様なのか分からない。

### ぴったり出る（YouTubeに公開時刻を予約している）

前半の一覧のうち、「明日の注目試合」と「資産動画」以外はすべてこちら。
夕方の4本は15時台に1回で作って、公開だけをYouTubeに預けている。
だから生成が何分かかっても、公開はその時刻ちょうどになる。

### 数分ずれる

| 時刻 | 枠 | なぜ |
|---|---|---|
| 19:00頃 | 明日の注目試合 | 動画を作るのが通知の後だから |

19時の回は、まず通知とSNSを19:00ちょうどに出し、そのあとで動画を作る。
生成に5〜10分かかるので、動画の公開は19:02〜19:07になる。
実測: 8/17は19:03、8/18は19:02、8/19は19:07。

`--publish-at 19:00` は渡してあるので、起動が早くて19時前に
作り終えた日はちょうどに出る。恒常的にちょうどにしたいなら、
動画の生成と投稿を通知より前へ動かす必要がある
(いまは「通知を最速で届ける」ことを優先した並びになっている)。

### 時刻を決めていない

| 枠 | なぜ |
|---|---|
| 資産動画 | 日付に依存しない内容だから |

GitHub純正のscheduleで起動しているので、0〜4時間遅れる。
球場や球団の話は今日でも明日でも同じなので、そこを直す価値が薄い。
名前も「毎日 夜」にしてあり、時刻は名乗っていない。

日次のように時刻を守りたくなったら、他と同じく cron-job.org から
起動して `--publish-at` を渡す。

## 「morning」という名前について

コードの中では夕方の4本を `morning` と呼んでいる。

もともとは朝に出す予定だった枠で、その後「日本時間の朝〜昼にMLBの
試合があるので、結果が確定するのは14時台」と分かって夕方へ動かした。
名前だけが当時のまま残っている。

いま変えられないのは、投稿の記録(`data/published_videos.json`)の
キーが `morning` `morning_player` … になっているため。名前を変えると
過去の記録と繋がらなくなり、健康診断も再生リストも全部ずれる。

なので **コードの中の名前は `morning`、人が読む文言は「夕方」** で統一する。
ログもコメントも、動画の説明文も「夕方」と書く。

| コードの名前 | 実際の時刻 | 人に見せる呼び方 |
|---|---|---|
| `morning`（mode=players） | 17:00 | 夕方 |
| `morning_voices` | 18:00 | 夕方 |
| `morning_press` | 18:00 | 夕方 |
| `morning_postseason` | 20:00 | 夜 |
| `longform` | 18:30 | 夕方 |
| `daily` | 19:00頃 | 夜 |
| `daily_soccer` | 19:00 | 夜 |
| `soccer_race` | 21:00 | 夜 |
| `weekly` | 日曜 22:00 | 夜 |
| `asset` | 22:00頃（決めていない） | — |

なお「日本時間の翌朝に試合がある」のような文の「朝」は本当に朝を
指しているので、そのままにしてある。
