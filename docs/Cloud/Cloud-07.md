# Cloud-07: 日本人選手のシーズンまとめの構成の見直し（構成案と台本の見本）

作成: 2026-10-04 PCのClaude。本人（10/4）「日本人選手の今シーズンまとめ、情報が局所的。もう少し広く概要をサラっと触れたあとに深いところに触れつつでもいい。特筆すべきスタッツとそのランキングとかさ」。今の枠は `scripts/season_topics.py` が材料を作り、`scripts/generate_asset_video.py` が「見出し。数字。」を順に読み上げている。

## 0章 最初に必ず

`docs/Cloud/Cloud-TEMPLATE.md` の0章の決まりに従う。読む順: `docs/Cloud/README.md` → この指示書 → 1章の材料。作業用ブランチは `cloud/07-season-structure`（セッションで決められていればそれ）。

## 1章 作るもの: `docs/Cloud/out/07_season_structure.md`

1. **今の構成の分析**: `data/season_topics.json` の日本人選手の回（`jp` があるもの。鈴木誠也・今永昇太・吉田正尚など）の `items` の並びを書き出し、「局所的」に感じる理由を3つまで（例: 概要より先に細かい指標が来る、順位が無い、など）。`scripts/season_topics.py` の作り方も読んで、どの関数がどの項目を作っているか対応づける。
2. **新しい構成の型**（4段）:
   - ①概要: 試合数・主な成績・球団の結末を1画面で
   - ②特筆スタッツ: リーグ順位つき（規定到達者の中で）。上位にある項目から最大3つ。順位の材料が無い項目は入れない
   - ③深掘り: Statcastのパーセンタイル・前年比など、②を裏づけるもの
   - ④締め: 来季につながる事実（契約・年齢など、材料にあるものだけ）
   打者・投手で項目がどう変わるかの表も。
3. **台本の見本を2本**（打者1人・投手1人。`data/season_topics.json` にいる日本人選手から選ぶ）: 新しい構成で、画面ごとに「画面の見出し／画面に出す数字／読み上げ」を表にする。**数字は材料の値だけ。** ②の順位が材料に無ければ「（順位の材料が必要: MLB公式のリーダーボードの○○）」と書き、PC側が足すべき材料の一覧に入れる。
4. **PC側が足すべき材料の一覧**: 項目・取り方（MLB公式APIのどの種類か。分かる範囲、推測は推測と書く）・なぜ要るか。

- 完成の条件: 1〜4がそろい、見本2本の数字がすべて `data/season_topics.json` の値と一致していること。

## 2章 決まり

- 材料に無い数字を作らない。推測は「推測」と書く。
- 「タイトル」は公式の表彰だけ。部門1位を「タイトル」と呼ばない。
- 率の順位は規定到達者の中だけ。値が小さいほど良い指標（三振率など）は向きを取り違えない。
- 盛らない（「圧巻」「完璧」など）。見出しに読点で区切るキャッチコピーを使わない。
