# Opus-02: 長編の構成表（1回目）のプロンプトの評価と改良、見本の構成表3つ

作成: 2026-10-05 コレスポのPCのClaude（エマ）。別アカウントのリポジトリ（作業一覧つき）で、Opus 5.5 に頼む作業。

- 成果物は作業をしているリポジトリの `collespo/` に、PRで出す。外部のAPIは使わない。秘密は書かない。

## 背景
長編（3分前後、2人の会話）を「1回目: 構成表 → 間: プログラムが足りない材料を公式APIで取る → 2回目: 章ごとの台本」に変える。構成表の形と機械の検査は `scripts/longform_plan.py`（`PLAN_PROMPT`・`validate`・`outline`）。いまの台本の指示は `scripts/generate_dialogue.py` の `CAST` と `NUMBERS_PROMPT`。

あなたに頼みたいのは、**1回目を書くモデルの立場で `PLAN_PROMPT` を使ってみて、プロンプトと検査を良くすること。**

## 読むもの
1. `scripts/longform_plan.py`（全部）と `scripts/test_longform_plan.py`
2. `scripts/generate_dialogue.py` の `CAST`・`NUMBERS_PROMPT`
3. `scripts/numbers_material.py` の `facts`・`panels`（材料と札がどう作られるか）

## 作るもの: `collespo/longform_plan_review.md`
1. **見本の構成表3つ**: 下の「材料A」で、`PLAN_PROMPT` どおりに構成表（JSON）を3通り書く（見どころの選び方を変えて）。それぞれ `validate` に通るか（手で確かめてよい。動かせるなら `longform_plan.py` を使う）。
2. **プロンプトの問題点**: 書いてみて迷ったところ、決まりがあいまいなところ、モデルが外しやすいところ。
3. **改良案**: `PLAN_PROMPT` の書き直し案（全文）と、`validate` に足すべき検査（例: lead の章がその日いちばんの出来事を扱っているか、同じ選手を2章に分けていないか）。足す検査はコード（関数）とテストの案まで書く。
4. **2回目（台本）への渡し方**: `outline` の形で足りるか。章ごとの台詞の長さの目安（全体1600字前後）をどう配るか。

決まり: 材料に無い数字を作らない。予想・理由の決めつけを章にしない。選手名はカタカナか漢字。見出しに読点で区切るキャッチコピーを使わない。
