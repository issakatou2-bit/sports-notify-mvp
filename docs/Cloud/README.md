# クラウドで作業する仕組み（docs/Cloud）

**使用量を食う作業の置き場。**PCが要らない作業を指示書にして置いておき、スマホのClaudeアプリの「Code」や claude.ai/code（クラウドのセッション）、または別アカウントのClaudeが拾って、指示書どおりに進める。2026-10-03 作成。

本人（10/3）:「使用量の食いそうな作業をそこにおいておいて、クラウドセッションも作業できるようにしておく。場合によっては新アカがやっても良いようにするってイメージ」

> フォルダ名は小文字の `docs/` の下の `Cloud/`。Gitに入っているのは `docs/`（小文字）で、Windowsは大文字小文字を区別しないため、`Docs/` で作るとGitHub上で2つのフォルダに分かれる。

## 分担

| 誰 | 何をするか |
|---|---|
| 本人 | 決める。スマホからクラウドに最初の一言を送る。公開してよいかを決める |
| PCのClaude（指揮役） | 設計・調べもの・**指示書（`docs/Cloud/Cloud-NN.md`）づくり**。クラウドから戻ったPRの中身を確かめ、取り込む（mainへのマージ）。本番（動画の制作・公開）に関わる変更はPCで行う |
| クラウドのClaude | 指示書どおりに、**新しいファイルだけ**を作る（文書・HTMLの手本・調べもの・コードの下書き）。作業用のブランチで作り、mainへのPRを出して終わる。マージはしない |
| 別アカウントのClaude（PCでもクラウドでも） | 置いてある指示書を拾ってよい。**拾ったときの決まりはクラウドと同じ**（作業用ブランチで新しいファイルだけ→mainへのPR）。PCで拾った場合も、本番のファイルへの反映は指揮役が確かめてから |
| Codex（「ヒロ」） | 別の作業場所（隔離したclone）で作業し、PRで出す。主な担当は SNSへの配信（Buffer・Bluesky）・サイト・定期点検・新PSの描画の一部。担当が重なるときはPCの共有メモで調整する（クラウドからは見えない） |

## 拾い方（同じ指示書を2人でやらない）

1. `docs/Cloud/` の `Cloud-NN.md` のうち、`作業記録.md` に「済」が無いものが未着手。番号を指定されていなければ、**未着手でいちばん番号の小さいもの**を選ぶ。
2. 始める前に、GitHubで **同じ `Cloud-NN` の題のPRが開いていないか**を確かめる。開いていれば別の指示書へ。
3. 始めたらすぐ、作業用ブランチで `作業記録.md` に「着手」の行を追記してpushし、**下書きのPR**を作る（ほかの人から見えるように）。
4. 終わったらPRを「レビュー待ち」にし、`作業記録.md` に「済」の行を足す。

## 置き場所

- 指示書: `docs/Cloud/Cloud-NN.md`（NNは連番。ひな形は `docs/Cloud/Cloud-TEMPLATE.md`）
- クラウドが作るもの: 指示書に書いた場所。決まっていなければ `docs/Cloud/out/NN_*.md` / `.html`
- 記録: `docs/Cloud/作業記録.md`（クラウドが日付つきで追記）

## 決まり

1. **元のブランチは `main`。**このリポジトリで GitHub に常にあるのは main だけ（PCの作業ブランチ fix-0907 は手元だけのもので GitHub には無い）。クラウドは `cloud/NN-短い名前` のブランチを作り、最後に main へのPRを作る。
2. **新しいファイルだけを作る。**既にあるファイルは書き換えない。とくに `scripts/`・`.github/workflows/`・`data/`・`web/`・`assets/`・`CLAUDE.md`・`AGENTS.md` は触らない（毎日自動で動画を作って公開している本番。data/ は自動のコミットで1日に何十回も更新される）。
3. **このリポジトリは公開。**PRに書いたこと・作ったファイルは誰でも読める。秘密（鍵・パスワード・トークン）は書かない、聞かない。
4. **正しさ。**数字・名前・日付は、Gitにある材料（`data/` の公式データなど）か、出典URLのあるものだけ。推測は「推測」と書く。作り話の例を本物のように書かない。
5. **公開しない。**YouTube・SNSへの投稿、ワークフローの手動実行はしない（鍵も無い）。
6. 返答とPRの説明は日本語。

## クラウドでは使えないもの

- PCのアプリ: VOICEVOX（読み上げ）、手元の ffmpeg、YouTube Studio、Windowsの書体（メイリオ）
- GPU
- Gitに入っていないもの: PCの共有メモ（`docs/HANDOFF.md`）、`docs/` の評価資料の多く、`build/` の見本、秘密の鍵
- 外部への通信は制限されることがある（推測）。取れなかったら「取れなかった」と書いて先へ進む

## スマホでの始め方

1. Claudeアプリの「Code」（または claude.ai/code）を開く
2. リポジトリ `issakatou2-bit/sports-notify-mvp`、ブランチ `main` を選ぶ
3. 最初の一言: **`指示書を読んで作業して`**（未着手でいちばん番号の小さい指示書を選んで進める。決まりは `CLAUDE.md` に書いてある）
   - 番号を決めたいとき: `Cloud-02 の指示書を読んで作業して`
4. 終わるとPRができる。PCのClaudeに「クラウドのPRを確認して取り込んで」と伝える

## PCのClaudeがPRを受け取ったら

1. 変更が新しいファイルだけか（既存ファイルの書き換えが無いか）を確かめる
2. 中身の数字・名前を材料と突き合わせる。推測と事実が分かれているか
3. 本番に使うもの（コードの下書きなど）は、PCで検査（`scripts/run_checks.py`）を通してから本番のファイルへ移す
4. 取り込んだら PCの共有メモ（`docs/HANDOFF.md`）に一行残す
