# Cloud-06: 動画の演出・アニメーションの設計書とHTMLの動く見本

作成: 2026-10-04 PCのClaude。本人（10/4）「全体に言えることだけど演出とかアニメーションとかもっと凝りたい」「画面遷移とか移り変わりもなさすぎる」。動画はPC側がPython（PIL）で1コマずつ描いている。**ここでは「どう動かすか」を決める設計書と、ブラウザで動く見本を作る。** PC側（Codex）がこれを見て描画に移す。

## 0章 最初に必ず

`docs/Cloud/Cloud-TEMPLATE.md` の0章の決まりに従う。読む順: `docs/Cloud/README.md` → この指示書 → 1章の材料。作業用ブランチは `cloud/06-motion`（セッションで決められていればそれ）。

## 1章 作るもの

### A. `docs/Cloud/out/06_motion_spec.md`（設計書）

今ある描画を読んで、足す動きを決める。読むもの: `scripts/ps_motion_template.py`（今の動き。入場と0.28秒の切り替え、`focus_plan` の行の強調）、`scripts/review_render.py`（シーズンまとめ・PSの話題の画面）、`scripts/ps_render_template.py`、`scripts/ps-brand-theme.json`。

| 項目 | 書くこと |
|---|---|
| 今ある動き | 何がどう動いているか（ファイル・関数名つき） |
| 足す動き | 1つずつ: 名前、何に使うか、長さ（秒）、動き方（イージング）、いつ使わないか |
| 画面の型ごとの組み合わせ | 表紙／一覧／順位表／比較／引用／勝ち上がり図／章の見出しカード で、どの動きをどの順に |
| 1コマずつ描く場合の書き方 | PILで描くときの式（進み具合 p から位置・透明度を出す式）。疑似コードでよい |

足す動きの候補（取捨選択してよい）: 要素の入場（下から少しずれて現れる）、数字のカウントアップ、読み上げ中の行の強調、章の見出しカード（ワイプ）、比較の棒が伸びる、勝ち上がり図の線が伸びる、順位表の自分の行が浮き上がる、立ち絵の小さな反応（うなずき・驚き。画像の差し替えか、少し揺らすだけ）。

決まり: **動きは情報を読ませるため。** 読み上げに追いつかない速さや、読む時間を削る飾りは入れない。Shortsの安全域（下18%・右13%）を守る。1本の中で同じ動きを使い回し、型の数を増やしすぎない。

### B. `docs/Cloud/out/06_motion_demo.html`（動く見本）

1080×1920 を縮小した画面1つで、A の動きを順に再生する（CSSアニメーションかJS、外部の読み込み無し）。再生・一時停止・速さ（0.5倍/1倍）のボタン。中身の例は実データを使う: `data/recap_history/2026-09-25.json`（村上2本塁打の日）の選手一覧と、`data/postseason.json` の勝ち上がり。

- 完成の条件: 設計書に「足す動き」が5つ以上あり、それぞれ長さ・イージング・使わない場面が書かれ、見本でその動きが見られること。

## 2章 決まり

- 材料に無い数字を作らない。推測は「推測」と書く。
- 見出しに読点で区切るキャッチコピーや不要な語りかけを使わない。
