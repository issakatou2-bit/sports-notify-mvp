# Opus-20: 型ごとの週次レポートを自動で作る（公開後24時間・7日）

作成: 2026-10-09 コレスポのPCのClaude（エマ）。

> **コレスポのコードとデータ**: 最新は公開リポジトリ `issakatou2-bit/sports-notify-mvp` の main（`https://github.com/issakatou2-bit/sports-notify-mvp/archive/refs/heads/main.tar.gz` を取って読む）。成果物はこのリポジトリの `collespo/` の下に作り、PRで出す。秘密は書かない。外部の有料APIは呼ばない（MLB Stats API など無料・鍵なしの公開APIは読むだけならよい）。本番のコードは直接変えない（取り込みはコレスポのPCのClaude）。
> **背景**: 2026-10-09 の分析ページ「コレスポの強みと伸ばし方」（要点: 再生の83%がShortsのおすすめ、登録者のフィードは2%。PSの試合の話題が最強（中央値233回）、毎日の17:00〜20:00枠は数十回。900〜1,000回で止まる回が多い。登録は約2,400回に1人。登録1,000人には「登録する理由」と1日の量が要る。11月からMLBの試合が無くなる）。

## 作るもの（`collespo/weekly_report/`）
1. `weekly_report.py`: `data/analytics.json`（日ごとの保存。各日に直近28日の動画別の再生・平均視聴率・登録・流入元）と `data/published_videos.json`・`data/published_assets.json`（動画IDと枠・公開日）から、**型ごと**（試合の話題・17:00成績・17:30コメント・18:00報道・19:00予告・20:00情勢・殿堂入り・長編・欧州サッカーなど）に、直近7日に公開した回の「公開後の再生の中央値・最高・平均視聴率・登録・1,000回を越えた本数」を出す。前の週との差も。保存が日ごとなので、公開後24時間・7日の値は最も近い日の保存から近似し、近似であることを書く。
2. 出力は Markdown（`docs/weekly/YYYY-MM-DD.md` に置く想定）と、型ごとの表。数字は材料にあるものだけ。
3. 検査（固定の小さな材料で）。
4. README: 毎週月曜に GitHub Actions で回して、レポートをコミットする形（ワークフローの案を書く。本番には入れない）。
