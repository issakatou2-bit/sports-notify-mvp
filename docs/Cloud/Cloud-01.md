## 1章 作るもの

### A. 17:00成績の新デザインのHTML手本 → `docs/Cloud/out/01_morning_v2.html`

1枚のHTML（外部の読み込み無し、CSSは中に書く）。縦長の画面（1080×1920 を縮小して表示）を**3枚**横に並べる。

| 画面 | 中身 |
|---|---|
| 1 表紙 | 対象日（日本時間）と「日本人選手の成績」。いちばん上の選手の名前と成績の要点を大きく |
| 2 1人ずつ | 選手名（大）・球団名・その日の成績（打者: 打数・安打・本塁打・打点・四球／投手: 投球回・自責・奪三振）。材料に順位があれば順位 |
| 3 一覧 | その日に出場した日本人選手の全員を1行ずつ |

- **材料**: `data/recap_history/2026-09-29.json`（米国9/29＝日本時間9/30の分。PSのワイルドカードシリーズで、村上宗隆・鈴木誠也・松井裕樹が出場。`players` の `name`・`team_jp`・`type`・`headline` などを使う）
- **色・書体の大きさ・安全域**: `scripts/ps-brand-theme.json`（`colors.stadium` の bg/ink/muted/accent/line/panel）、描き方の考え方は `scripts/ps_render_template.py`（見出しの大きさ、項目のラベルと値）
- **Shortsの操作部品と重ならない範囲**: 上の約8%・下の約18%・右の約13%には大事な文字を置かない。この範囲を半透明で重ねて見せる**切り替えボタン**を付ける（手本の確認用）
- **キャラクター**: 画像は使わない。「立ち絵の位置」として、左の中段（下18%より上）に枠だけを描く
- 今の17:00の構成（どの順で何を見せているか）は `scripts/generate_morning_short.py` の `render_intro_players`・`render_intro` 付近を読んで、上の3枚に対応づけた説明を、HTMLの下に短く書く
- 完成の条件: 3枚がそろい、材料の数字と一致し、安全域の重ね表示が動くこと

### B. PSの話題の情報源の洗い出し → `docs/Cloud/out/01_ps_sources.md`

いまの話題の回（`scripts/ps_story.py`）は「MLB公式の成績表」と「番記者のBlueskyの投稿（`data/local_reporters.json`）」だけを使っている。足せる情報源を、次の表で洗い出す。

| 情報源 | 何が取れるか | 取り方（API・RSS・URLの形） | 使ってよいかの注意（規約・引用の範囲） | 確認できたか |
|---|---|---|---|---|

- 必ず入れるもの: MLB公式YouTubeのハイライトのコメント（Gitにある `data/local_voices.json` の形を説明）、MLB.com の記事、各球団の公式発表、Reddit r/baseball の試合後スレッド、Baseball Savant のシリーズ単位の数字、ESPN 等の見出し
- 各情報源について、**カブス対パドレスのワイルドカードシリーズ（9/29〜9/30、パドレスが2勝0敗）**で何が取れそうかを1行ずつ。外部への通信ができなければ「未確認」と書き、URLの形だけ示す
- 最後に「おすすめの順番」（足す価値・手間・規約の安全さ）を3つまで、理由つきで
- 完成の条件: 表が6行以上、各行に「確認できたか」がある

## 2章 正しさと書き方の決まり

- 数字・名前・日付は材料か、出典URLを示せるものだけ。**推測は「推測」と明記。**
- 材料に無い選手・試合・数字を作らない（例として見せる場合も、材料の実際の値を使う）。
- 選手名・球団名は材料の日本語表記に合わせる（`data/recap_history/*.json` の `name`・`team_jp`）。
- コレスポの方針: 主対象はMLBをある程度見ている人。日本人選手を前に出す。数字が言っていない程度の言葉を使わない（「圧巻」「完璧」などで盛らない）。
- 引用（Bで扱う情報源）は出典つき。規約が不明なものは「不明」と書く。
