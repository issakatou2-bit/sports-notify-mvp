## まとめ

- 今の個人の回は「今季の成績1行 → 昨季との比較 → （まれに）リーグ順位 → Statcastの端2つ → 球団の結末」。**順位が付いているのは9人中1人（岡本和真の本塁打ア・リーグ6位）だけ**で、Statcastは良し悪しに関係なく端の2つが機械的に選ばれる。これが「局所的」の正体と見る。
- 新しい型は **①概要 → ②特筆スタッツ（順位つき）→ ③深掘り → ④締め** の4段。①に球団の結末まで入れ、②で「リーグの中でどこにいるか」を言い、③は②を裏づける数字だけにする。
- **②と④の材料が今は無い**。②は「順位を10位以内のときだけ残す」今の作り方を変えて、順位と母数（○人中）を毎回残せば作れる。④の契約は MLB Stats API には無いと見られる（推測）ので、当面は年齢（同じAPIの選手情報）と自己最多で締める。

### 1-3. 「局所的」に感じる理由（3つ）

1. **リーグの中での位置がほとんど出ない。**順位は4項目しか調べず、しかも10位以内のときだけ残すので、9人中8人は順位が1つも無い。「26本塁打」が多いのか少ないのか、見る人が自分で判断するしかない。
2. **Statcastの2つが、話の流れと関係なく選ばれる。**50から最も離れた2つを機械的に取るため、良い面と悪い面が混ざり、主な成績ともつながらない。例: 今井達也は「与四球率の高さはリーグ上位1%　速球の回転数はリーグ下位2%」、菅野智之は「被期待wOBAの高さはリーグ上位1%　被期待打率の高さはリーグ上位1%」。与四球率・被期待wOBA・被期待打率の「高さが上位」は投手には望ましくない向きだが、「上位」という言葉で良いことのように聞こえる。
3. **概要が1行で、すぐ細部（昨季との2項目の比較）に入る。**球団の結末は最後に置かれ、「どんな年だったか」の全体像（成績と球団の結末）が最初にそろわない。昨季との比較も本塁打・打点（投手は勝利・奪三振）の2つに固定。

## 2. 新しい構成の型（4段）

| 段 | 何を言うか | 決まり |
|---|---|---|
| ① 概要 | 主な成績を1画面で＋球団の結末 | 今の「今季の成績」と「球団の結末」を1つにまとめる。移籍した年は「2球団の合計」と書く |
| ② 特筆スタッツ | リーグの中での順位つきの項目を最大3つ | **順位の材料がある項目だけ**。率（打率・OPS・防御率など）は規定到達者の中の順位、数える項目（本塁打・奪三振など）は全員の中の順位。「ナ・リーグ○位（規定打席到達○人中）」のように母数を書く。順位の上の項目から選ぶ。部門1位でも「タイトル」とは呼ばない（公式の表彰だけをタイトルと呼ぶ） |
| ③ 深掘り | ②を裏づける数字（Statcastのパーセンタイル・昨季との比較・自己最多） | ②の項目に関係するものを先に選ぶ（例: 本塁打→バレル率・ハードヒット率）。関係するものが無いときだけ、今の「端の2つ」を使う。値が小さいほど良い指標は、向きを言葉で言う（今の `statcast_phrase` のやり方を残す） |
| ④ 締め | 来季につながる事実 | 年齢・契約・自己最多など、材料にあるものだけ。材料が無ければ④を省き、①の球団の結末で終える |

### 打者・投手で変わる項目

| 段 | 打者 | 投手 |
|---|---|---|
| ① 概要 | 試合・打率・本塁打・打点・OPS／球団の結末 | 登板・勝敗・防御率・投球回・奪三振（セーブ・ホールド）／球団の結末 |
| ② 特筆スタッツの候補 | 本塁打・打点・盗塁・四球（全員の中）、打率・出塁率・OPS（規定打席到達者の中） | 勝利・奪三振・セーブ・ホールド（全員の中）、防御率・WHIP・9回あたり奪三振（規定投球回到達者の中）。救援投手は規定に届かないので、セーブ・ホールド・登板数を使う |
| ③ 深掘りの候補 | バレル率・ハードヒット率・平均打球速度（本塁打・長打）、四球率・ボール球を振る割合（出塁）、守備で防いだアウト・走る速さ（守備・走塁）、昨季との比較 | 空振りを取る割合・奪三振率（奪三振）、与四球率（制球）、被バレル率・被ハードヒット率（被弾）、速球の平均球速・回転数、昨季との比較 |
| ④ 締め | 年齢・自己最多・（契約） | 同じ |

## 4. PC側が足すべき材料

| 項目 | 取り方（MLB公式API） | なぜ要るか |
|---|---|---|
| 順位と母数（数える項目） | 今の `league_rank` と同じ `stats?stats=season&group=hitting|pitching&leagueId=103|104&playerPool=ALL&gameType=R`。**順位を10位以内でなくても残し、母数（並べた人数）も一緒に残す** | ②の「ナ・リーグ○位」。今は10位より下だと何も残らない |
| 順位と母数（率の項目） | 同じ呼び出しで `playerPool=QUALIFIED`（今もOPS・防御率で使っている） | ②の「規定打席到達○人中○位」。率の順位は規定到達者の中だけで言う決まりのため |
| ②の項目を広げる | 同じ呼び出しの戻り値にある `rbi`・`avg`・`obp`・`stolenBases`・`baseOnBalls`（打者）、`wins`・`whip`・`saves`・`holds`・`strikeoutsPer9Inn`（投手）。キー名は推測（今のコードで確かめてあるのは `homeRuns`・`ops`・`strikeOuts`・`era`） | ②で「順位の上の項目から3つ」を選べるようにする |
| 年齢 | `people/{id}`（今も `player_topic` で呼んでいる）の `currentAge`・`birthDate`（推測: 項目名） | ④の締め |
| 契約 | MLB Stats API には契約の年数・金額は無いと見られる（推測）。入れるなら球団の公式発表など別の出典が要り、出典つきで書く | ④の締め。出典が用意できなければ使わない |
| 公式の表彰 | `people/{id}/awards`（推測: エンドポイント名）など | 「タイトル」と呼んでよいのは公式の表彰だけ。部門1位とは分ける |
| ③を②に結びつける | 今の `savant.fetch` の全項目（すでに1回で取れている）から、②の項目に対応する列を選ぶ（例: 本塁打→`brl_percent`・`hard_hit_percent`、奪三振→`whiff_percent`・`k_percent`） | ③を「端の2つ」ではなく、②の裏づけにする |
| チームの試合数 | `standings`（今の進出争いの材料にある `w`・`l` の合計）など | 規定打席・規定投球回の線を正しく出す（162試合と決めつけない） |
