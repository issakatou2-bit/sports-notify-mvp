# 日本代表の親善試合

既定停止。本人が `COLLESPO_SOCCER_NATIONAL=on` にしたmain実行だけ制作・予約する。現地時刻を日本時間へ変換し、ESPNのhomeAwayを開催国・ホーム開催の根拠にしない。大会名は「親善試合」、放送案内は扱わない。

## 時刻と台帳

- 前日18:00取得→19:30予告。前日20:00を過ぎた遅延実行は予告を作らない。
- 19時台開始は21:15・21:40・22:00に終了を再確認し、22:00を狙う。制作開始が遅れれば20分以上先へ予約する。未終了は翌朝に再確認。
- 20時以降開始は翌朝7:15取得→8:00結果。11/17 22:10開始は11/18朝。
- GitHubのscheduleには遅延がある。定刻公開は保証できず、未来の予約がなくなれば公開直前検査で停止する。
- `data/published_videos.json` の `soccer_national/YYYY-MM-DD` を使い1日1本。`national_mode`・`national_event_id`・`national_squad_page` を共通書込み器で追記する。結果は別の日にも同じ試合を再投稿しない。
- 既存の `short_content`・`sanity --strict`・`publication_writer` を使用。SNSは `buffer_daily.SOURCES` の `collespo-national-social` 成果物から既存の公開確認・重複防止へ渡す。19:47/23:47の既存回収枠で拾う。SNS側の既存切替も必要。

## メンバーを足す

`data/soccer_national_squad.json` は未発表の空欄だけ。JFAの発表後にClaudeが一次資料から記入する。

```json
{
  "version": 1,
  "announced_at": "発表日時のISO8601・時差付き",
  "source_url": "https://www.jfa.jp/実際の発表ページ/",
  "window": "2026-11",
  "season": "2026/27",
  "players": [
    {"name_en": "ESPNと辞書に一致する氏名", "club": "発表時の所属クラブ", "position": "GK"}
  ]
}
```

位置は `GK / DF / MF / FW / MF/FW`。試験用の架空例は `scripts/fixtures/soccer_national_squad.example.json`。`sample: true` の例は本番へ流せない。未発表・未来の発表・対象月違いは生成しない。

日本人の `name_en` は `data/soccer_player_names.json` のconfirmed氏名・日本語名・読みと一致必須。新しい招集選手が未登録なら先にJFAで氏名を確認し、同辞書と既存の `player_kana.json` の読みの仕組みに登録する。ローマ字表示へ逃がさない。

全選手を名簿順の2〜3人ずつに分ける。発表後の10:15取得→12:00の枠で、予告・結果の日を避けて未配信の分冊を進める。最後が1人にならないよう分け直す。発表が遅く全冊が窓に収まらない場合は、事前に発表日と人数から判断する必要がある。30人が2日で全員出る仕組みではない。

クラブ成績は既存 `soccer_games.json: games[].season_players[]` の氏名・所属・scope=season・取得時刻・出典が一致する時だけ。対象季の値で7日以内、0と欠測を区別。季の欄がない従来形式は当該取得日の欧州の年またぎ季として限定する。リーグ名・時点とともに出し、移籍前クラブ・前季・古い値・曖昧な複数値は使わない。成績がなければ発表された所属と位置だけ。

## ブラジル・パラグアイを後から足す

今回の予告は招集を根拠にしていない。相手国の招集発表を入手したら、発表URL・日時・team ID（ブラジル205、パラグアイ210）・ESPN athlete ID・英語氏名・日本語名・所属を保存材料へ記録する。得点者名を使うには既存 `data/player_kana.json` の `names[ESPNのdisplayName]` と読みを、確認した日本語名で登録する。英語氏名は完全一致で、同姓や部分一致ではつながない。未登録は国名で「ブラジルが1点」の形にする。

招集だけから出場・先発・得点を推測しない。相手の招集名簿を全員紹介する別回は今回追加していない。

## 不完全な得点経過

`keyEvents[].scoringPlay` かつ `shootout=false` の各チーム件数が、そのチームの最終スコアに一致する時だけ得点者を使う。重複ID・チーム不明は停止。合計点だけが一致しても不可。9/24の3-1はイベント1-1しかないため得点者をすべて省く。前後半の値は両チームとも合計が最終スコアに一致する場合だけ使う。

11/02 11:30依頼で事実の基盤を修正。日本の直近・前回対戦・当年成績は `data/soccer_national_results.json` が唯一の正。Claudeが照合した全大会一覧を渡されたまま保存し、大会別ESPN日程から日本の履歴を組み立てない。当該eventの終了確定結果は別欄 `current_result` で追加し、同日・同相手が一覧にあれば得失点を照合して1試合だけ数える。過去の結果見本は当該試合日までに切り、将来の結果を混ぜない。PK戦は引き分けとして数え、PK得点を得失点に足さない。

全大会ESPN日程 `soccer/all/teams/{id}/schedule` は日本について未収載結果の検知にだけ使う。一覧の最終試合より新しい終了済み試合が未収載、既知結果の得失点が不一致、または `checked_at` から21日超なら警告を出し、日本の直近・連勝・年間成績・前回対戦・再戦の断定を省く。21日は実装上の保守的な上限で、網羅の保証ではない。出力の `history_warnings` とgateに残し、短くなって素材が足りなければ見送る。11/16の予告時に11/14の結果が一覧へ未反映なら、ESPNにその結果があれば日本の履歴を省く。

相手国も `soccer/all/teams/205/schedule`・`210/schedule` を使うが、網羅性を前提にせず、日付つきの結果を1試合伝える。「直近」「連勝」や大会名を推定しない。日本の予告はブラジルとの6月W杯再戦、キリンカップ優勝、全大会成績を軸にする。得点者は人ごとに集計。逆転は得点順にビハインドのある勝利、決勝点は勝者が相手の最終得点を1点上回るゴール。欠測の時はどちらも言わない。

`check` は台本と埋込み材料の一致だけでなく、その時点の確認済み一覧を読み直し、前回・直近・全大会成績と一覧SHA256を再照合する。古い「前回は2025年」「5試合全勝」を材料ごと戻しても停止する。履歴を更新した後は材料と台本も作り直す。

27秒未満は `length_level` を実測ごとに進め、結果は1=当年全大会成績、2=同じ試合の得失点、3=当該会場、4=直前の試合の順に補う。予告は当年成績を最初から話し、2=得失点、3=確認済みキリンカップPK勝利の順。追加材料なし・再測定も不足・60秒超過は見送り。声設定は変えず、無音や話速では埋めない。題は「日本対ブラジル 11/14 19:15」「日本2-1ベネズエラ 上田綺世2得点」の形を共通の題フォーマッターへ渡す。

## 保存と再制作

公開用生応答・材料・台本・音声・レイアウト・sanityは `build/soccer_national/`。日付範囲でなく1日ずつscoreboardを呼ぶ。取得先は無認証の既存ESPN API、今回のローカル見本は取得済みファイルだけを使った。

ローカルの再制作は `build/quality/national_samples.py`。前回の `wt-soccer-sample/build/quality/local_core.py` を流用したVOICEVOX Core 0.16.2 CPU。必ずheavy_waitの中で使い、専用Coreをfinallyで閉じる。VoiSona要求はない。音声・書出し・試験の結果は `build/quality/*.log` / `*.exit.json` に記録する。
