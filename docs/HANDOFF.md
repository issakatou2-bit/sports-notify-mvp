  `run_checks.check_splits_reader` が寄せ忘れを見つける。

- **まだ直っていない場所: `slide_insight`**（9/6から未修正。投手/打者・
  ER/失点・欠測の意味の誤りが残る）。

## 解説視点の問い合わせエンジン（2026-09-15 着手・骨格まで）

主語を渡すと、膨大な材料から**意味のあるものだけ**が返る仕組み。
返ったものを動画の1枚に使うか、記事にするか、サイトに載せるかは
呼んだ側が決める。**出すのはJSONなので、動画とサイトで同じものを読む。**

- `scripts/mlb_trends.py` … MLB APIから切り口ごとの成績（API4回/人）
- `scripts/insight.py` … 「言えること」に変換。tone と sure を付ける
- `scripts/test_insight.py` … 偶然を傾向として語らないかの検査

**いちばん危ないのは、数字が全部正しいこと。**「直近5試合で打率.400」は
20打数8安打で偶然の範囲。検算では捕まらない。同じAPIで曜日別も取れて、
村上宗隆は1日目.300（40打数）/ 4日目.103（39打数）と**昼夜より大きな差**が
出る。昼夜が言えて曜日が言えないのは「意味が想像できるか」の違いで、
計算では決まらない。**切り口は登録制**（`mlb_trends.SPLITS`）。

返すものに付く2つ:
- `tone` positive/neutral/negative … ポジティブな枠では negative を外す。
  戦略・展望の回では要る（下降を知らないと「PSを勝ち抜く条件」が書けない）
- `sure` high/low … low は「事実として置くだけ」。直近35打数4安打は
  「上げている」と言わず、打数と安打をそのまま置く

判定は**確率**で行う（打数の下限ではない）。今季.204の打者が

```
満塁 5打数2安打(.400)  … 偶然でもこうなる確率 27%  → 出さない
初球29打数10安打(.345) …                     6%  → 事実として置く
終盤42打数9安打(.214)  …                    50%  → 出さない
```

打数で切ると5打数と29打数を区別できない。**確率なら、少ない打数でも
極端なものは拾える。**そのぶん切り口を増やしても安全になった（12個）。

**曜日別だけは別扱い**（`NOT_TAKEN`）。打数が集まるので確率では落ちず、
7通り試せばどれかが極端になる。意味が想像できない切り口は最初から取らない。
